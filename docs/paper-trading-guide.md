# PAPER 实时模拟策略使用指南

本功能只做本机前向模拟，不连接实盘下单。行情固定 Alpaca IEX/raw；示例策略及默认成本不构成收益承诺。工程状态与验收证据见 [实施计划](paper-trading-plan.md)。

## 开始使用

1. 应用默认进入模拟工作台。在“设置与备份”分别输入 Alpaca API Key 和 Secret，保存后单独执行“只读检查 IEX 与资产权限”。保存不等于验证成功；没有凭证仍可查看历史。不要把密钥粘贴进源码、报告或聊天。
2. 在“标的池”输入股票/ETF 代码并选择类型，点击“验证并添加”。仅支持 active、tradable 的美国交易所股票资产；ETF 标签需自行核对。最多 10 个标的，非归档实例占用标的不能移除。
3. 点击“新建策略”，依次选择模板、填写标的与结构化参数、配置本金/费用/滑点/仓位上限，最后审阅创建。无需编辑 JSON。跨页保留草稿，成功创建或明确放弃后清理；每个实例账户独立，行情共享。
4. 创建后进入详情，必须单独点击“启动 / 恢复”。预热最多 300 根常规时段 bar，仅用于指标，不产生过去成交。缺数据保持“数据不足”；权限、日历或 worker 故障会暂停，请查看活动原因。
5. 总览显示账户状态、数据质量、观察跨度、待核对和最近活动；进入详情查看持仓、成交、绩效与控制。比较、数据与核对、设置与备份各有独立导航。
6. “高级终端”保留原布局及 `PORT`、`ALRT` 等功能。原 `PAPER` 命令提供进入同一工作台的按钮，不维护第二套控制界面；PAPER 不支持弹出窗口。

SMA 默认 `{ "fast":10, "slow":30, "quantity":1 }`；RSI 默认 `{ "period":14, "lower":30, "upper":70, "quantity":1 }`；突破默认 `{ "lookback":20, "quantity":1 }`。窗口需满足 `2–299`、快线小于慢线、RSI 下阈值小于上阈值等校验；quantity 为整数股。RSI 是简单窗口算法，平盘为 50。

## 资金、成交与运行控制

- 默认示例本金 10,000 USD、每单费用 0 USD、滑点 0 bps（可调整）；费用和滑点都在创建时冻结。仓位上限是“单标的含买入费用成本 / 初始本金”，不是按即时净值计算的权重。
- 仅现金账户、整数股。买入资金不足整单拒绝，不自动缩量；不得卖空。卖出资金立即可用，不模拟券商 T+1 资金限制。
- 已完成分钟 bar 驱动信号。信号之后的新鲜同源成交参考才可能成交；参考来自轮询观察，不承诺是交易所实际下一笔成交。60 秒没有有效参考、收市或暂停就取消意图，不用旧收盘价补单。
- 买价为参考价 × (1 + 滑点 bps/10000)，卖价为参考价 × (1 − 滑点 bps/10000)。账本单位为整数微美元；比例计算 half-up 舍入，手续费计入成本或卖出净额。
- **暂停**取消待成交意图并保留仓位。暂停时可能只剩旧价估值，必须查看 stale/missing 和价格时间。**恢复**先重新预热，不补做中断期间交易。
- **请求模拟清仓**运行、暂停或已结束但未归档的实例均可在常规交易时段请求，不需要恢复策略。它暂停策略信号、取消旧意图，按新参考价格卖出，完成或超时后保持暂停；原本已结束的实例保持 ended。拒单或超时可能仍有持仓，务必查看成交及剩余仓位。
- **结束**取消未成交意图并冻结结束时结果，不伪造成交；仍有持仓时明确保留。结束后不能重启策略或继续公司行动记账；仍可单独请求模拟清仓，产生新的明确成交及净值记录。**归档**保留历史且不再允许清仓，请在归档前处理所需仓位。复制配置并修改会创建新实例，旧配置和曲线保持。

## 公司行动与数据质量

系统不会从价格跳变猜测拆股。相邻收盘价变化达到 40% 会暂停并要求核对。

在“数据与核对”录入股息或拆股/反向拆股，填写唯一行动 ID、代码、带 Z 的 UTC 生效时间、每股现金或新旧股数比例。确认摘要同时显示纽约时间及受影响账户当前持仓。系统按**当前持仓**调整所有尚未结束的相关实例，并先暂停它们；这是人工核对入口，不会重演过去的持仓。请在恢复该标的策略之前及时处理，不能用后来的持仓假装历史除权日持仓。已结束实例除用户单独请求清仓外保持结束时账本，归档后完全保留结果。

存在碎股时必须明确提供现金替代价。股息、成本分摊、碎股现金及账户变动留痕；跨账户调整同事务，任一账户失败则全部回滚。相同 ID 及内容重复提交不重复记账，相同 ID 改内容会拒绝。行动提交时间与输入生效时间分别留存。拆股后没有行动之后的估值价时记为 missing，不把旧价乘以新股数。

“确认已核对公司行动”是你的人工声明，不代表自动核验。新行动或可疑跳变会再次要求核对。未核对时报告不宣称完整总回报。

行情采集仅限日历已覆盖年份，目前为 2026；包括美国夏令时、节假日及半日市。未知年份停止，需要更新并验证 `calendar.ts`，不能猜测开放时间。非交易时段不算数据缺失；运行内的暂停、网络中断和缺 bar 都会影响覆盖率。

## 历史和比较

- 净值 = 现金 + 持仓估值；总盈亏 = 净值 − 初始本金。平均成本法下应满足“已实现 + 未实现 + 股息等现金收益 = 总盈亏”。缺价格时不报告确定净值。
- 每分钟以及成交/公司行动时保存净值，含每个标的的估值时间与质量。同一时刻多笔成交最终保存该时刻最终账户状态；成交本身逐笔留存。
- 成交、净值、运行事件按实例和纽约日期独立分页，每类 100 条，截止日包含全天，夏令时按纽约日历换算；切换类型保留各自页码，日期变化回到第一页。曲线只显示当前页采样。详情绩效是**创建至最近采样的完整观察期**，与明细日期筛选独立，不重设本金。
- 日/月收益按纽约日期分组并以上期末净值为基准。首末期及缺口明确标记不完整。最大回撤来自分钟及成交采样，不是 tick 级最大回撤；不提供短期年化收益或 Sharpe。
- 完整平仓样本统计从持仓大于零到清零的卖出事件，部分卖出不算独立完整平仓；拆股数量也参与统计。样本量不证明稳定盈利。
- 覆盖率以开始到最后观察点的常规时段“标的 × 分钟”为分母、实际实时 FRESH bar 为分子，包含暂停时段；预热/迟到补拉不伪装实时覆盖。观察时长、缺口和公司行动声明一起判断。
- 选中至少两个实例比较。只使用各实例都有真实采样的共同时间起止，以共同起点净值归一；没有两个共同点则不比较。对比不使用不同本金的绝对盈亏。长区间曲线最多约 2000 个展示点，收益计算用完整账本；旧价和缺失段不连线。

## 备份、导出与恢复

CSV 是所有模拟成交的查看格式；完整 JSON 包括 14 张业务表、源码快照和元信息。SQLite 导出使用数据库 backup API，包含 WAL 中已提交的数据；不要自行只复制运行中的 `.sqlite` 主文件。

从“设置与备份”确认影响后选择 JSON 或 SQLite 备份准备恢复。系统校验结构版本、外键、账户、现金流水余额、检查点、成交/事件及源码哈希，生成独立 `paper-restored-*.sqlite`，并保存当前库的一致性 `paper-before-restore-*.sqlite`，之后才原子切换启动指针。当前服务停止，按提示退出并重启。取消或校验失败不会切换指针；原库始终保留。JSON 恢复限制 256 MiB，大账本使用 SQLite。

数据库位于 Electron userData，macOS 通常在 `~/Library/Application Support/openterminal/`（以当前应用路径为准）；初始文件为 `paper-trading.sqlite`，恢复指针为 `paper-database.json`。数据库损坏或写入失败会停止运行，不能自动清空库继续。需要人工回退时先完全退出应用、保留当前文件和指针，再选择已验证备份恢复；不要边运行边替换数据库。

导出文件使用独占创建，已有目标文件会报错，请选择新的名称。未提供自动删除历史或覆盖唯一备份功能。

## 本机运行和中断

应用最小化/隐藏时主进程调度继续；完全退出或电脑休眠时不能跟踪。休眠/恢复、调度长时间中断和异常重启都会取消旧意图、记录中断并预热，不补做交易。人工暂停不会在重启后偷偷恢复。

首次交付尚需用户操作核验最小化、休眠/唤醒以及界面交互；助手没有启动页面。Windows/Linux、签名及公证没有验证。

持续采集必须在 2026 已知常规交易日 09:30 之后，且距收盘超过指定分钟数。输出仅含 source/feed、时间、有效性、请求数、状态码/配额和缺口摘要，不含密钥、认证头或价格响应正文；不触及用户账本或订单 API。权限错误或 429 停止并记录失败，不换源。JSONL 的 `verified` 只说明本次基础采集条件，不证明策略盈利或实际界面验收通过。

## 扩展 TypeScript 策略

入口为 `src/strategies/templates.ts` 和 `registry.ts`。增加模板种类、纯 `onBar` 等价计算分支、zod 参数 schema、requiredBars，然后添加确定性无界面测试。输入是只读 bars/account/parameters/state；输出仅包含 intents 和 nextState，不直接修改账户、不访问凭证或下单。

策略源码及可执行体哈希、build、state schema 冻结到 strategy_versions。改代码/参数应新建实例；旧版本不可用会暂停，不能自动升级旧运行。构建方式变化也可能改变版本哈希，需检查运行兼容性。worker 默认 1 秒、64 KiB 输出限制及内存限制，仅是可信本地代码的故障隔离，不是恶意代码沙箱。

未来消息适配器只能独立消费 repository.events(afterCursor, limit) 的已提交 StrategyEvent，按 eventId 去重；发送失败不得回滚成交。本版没有发送器、平台 SDK、发送队列或通知 UI；未来发送仍需另外授权和实现。
