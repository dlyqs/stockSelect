# 实时模拟策略跟踪改造计划

创建日期：2026-09-28。工作区：`/Users/git_local/openterminal`。

本文件是后续实施的默认执行入口与阶段状态唯一来源。规划不代表功能已经实现。

## 目标与范围

在现有 OpenTerminal 上增加个人使用的实时模拟策略工作台：人工选择最多 10 个不同美股股票或 ETF，少量 TypeScript 策略使用真实行情持续前向运行，每个策略实例拥有独立初始资金与账户，按统一规则自动虚拟成交，永久保存运行记录并比较表现。系统不接实盘下单。

已确认：TypeScript；独立模拟账户；自动虚拟成交；仅本机运行，应用运行且电脑未休眠时跟踪，退出或休眠记录中断。首版不开发通知提醒，未来预留社交媒体消息发送边界。

包含：手选标的池、代码策略模板、参数与版本管理、分钟级行情、资金及持仓约束、模拟成交、交易/净值持久化、历史查询、策略对比、恢复和数据质量展示。

不包含：回测、参数自动寻优、全市场实时筛选、Python 服务、实盘交易接口、融资融券、期权、桌面/声音/邮件/社交消息发送、新的社交平台凭证管理。原有终端功能保持可用；不扩展原有 `ALRT`、不让新策略事件触发它。未来社交发送需另行授权和实现。

## 歧义检查与产品边界

架构所需的三个选择均已由用户确认。以下为供审阅的首版具体设计，审批执行即以该版本为契约；策略参数不表示收益推荐。

- 股票与 ETF 均以买入持有/卖出平仓方式模拟；反向 ETF 通过买入该 ETF 表达看空，不实现借券卖空。指数只能作为后续信号参考，不能当作股票直接成交。
- 全局最多 10 个不同交易标的，多策略共享行情订阅；首版建议 3 个策略模板，可创建少量参数不同的运行实例。
- 每个运行实例可配置美元初始本金、标的子集、仓位上限、手续费和滑点；运行后冻结配置。更改代码、参数、本金或标的池要创建新实例，旧实例可归档，不能覆盖历史。
- 默认示例本金 10,000 USD；仅整数股、现金账户、不允许负现金/负持仓、不在运行中入金出金。模拟卖出资金可立即复用，不模拟券商 T+1 可用资金限制，界面明确标注。
- 仅美股常规交易时段，允许隔夜持仓；一分钟已完成 bar 驱动策略。盘前盘后只展示原有行情，不参与新策略成交。
- 示例采用 SMA 双均线、RSI 阈值、前 N 根 bar 突破三类确定性策略。共用仓位约束，默认不配置盘中实时止损；所有退出条件均在分钟结束时判断，避免暗示 tick 级风险控制。
- “稳定盈利”是长期观测目标，不是程序自动认证结论。展示观察时长、样本量、成本后收益、最大回撤、月度表现、数据覆盖率与中断；不凭少量交易显示“已验证稳定盈利”。

## 现状与可行性

当前 Electron/React/TypeScript 架构、主进程网络、IPC 和图表适合增量改造。复用 UI、凭证管理、日志、导出及适当的纯指标函数。无需引入 LEAN、Lumibot 或 NautilusTrader。

现有 `PortfolioManager` 只有手工持仓，`PortPanel` 的曲线来自当前持仓重建，不是策略账本；新模块需独立保存真实运行事件。现有提醒日志只保留 200 条，不能充当策略事件库。

需要先验证的工程风险：

1. 免费 IEX 数据的权限、目标 ETF 覆盖及实际新鲜度不是已验证承诺。首选 Alpaca IEX，能力检测失败时明确停止，不能把延迟源自动当作实时源。没有密钥仍可做离线逻辑验证，不能声称真实行情验收通过。
2. Electron 31 的 Node 运行时不能假定提供 `node:sqlite`。优先评估适配 Electron ABI 的 SQLite 驱动（例如 `better-sqlite3`）；Phase 1 验证原生依赖构建、worker 加载和打包方式，再冻结选择，不为此顺带全量升级框架。
3. 原有 `marketHours.ts` 节假日表只覆盖 2026 年。新增可验证的交易日历来源/年度覆盖检查；覆盖未知时停止调度，不猜测交易日。夏令时、半日市纳入测试。
4. 行情价格口径、分红和拆股影响长期收益。新账本使用未复权成交价格；公司行动使用显式账务事件，不能与图表的复权价格混算。
5. 免费数据无法保证精确市场成交，报告始终标注“模拟”和来源；成果是可审计的前向跟踪记录。

## 数据与执行契约

### 行情

独立 `MarketDataService` 获取 Alpaca IEX 分钟 bar 和成交参考价格，所有策略复用；不从 renderer 缓存或 150ms 合并后的 tick 反推完整 OHLCV。优先增量请求，固定 source/feed，保存 UTC 市场时间与本地接收时间。

bar 结束后等待供应商返回再处理，不承诺整分钟零延迟。参考设计：结束后 5 秒开始获取，最多在结束后 60 秒内受控重试；过期则记为 missing，不触发该 bar 的新订单。迟到或更正数据存修订记录，不回写已发生策略决策。启动时最多加载 300 根 bar 预热，预热数据不产生历史成交；指标窗口跨常规交易日延续，不用零成交假 bar 填洞。

同一实例每个 bar 批次执行一次；其依赖标的必须满足完整性与新鲜度要求，否则跳过并记录原因。基于 `(source, feed, symbol, interval, market_time)` 去重。休市与运行故障缺口分开统计。

### 策略与模拟成交

策略接口建议为 `onBar(context) -> { intents, nextState }`，输入为只读行情、账户、参数和显式状态；不能直接修改账户。输出为买卖意图和原因，由执行器检查资金、数量、仓位与标的许可。执行顺序固定：先卖后买，同侧按 symbol 排序，避免遍历顺序造成资金分配漂移。

信号产生后等待新的有效行情参考：同 feed 的首个市场时间晚于信号的成交价格，在收集窗口内到达才允许虚拟成交。首版优先复用轮询获取 latest trade，明确这是“轮询观察价”而非交易所保证的下一笔成交。不得用刚结束 bar 的收盘价或随后才知道的 bar 开盘价倒填成交。超过 60 秒、行情时间不合格或遇到收市则取消待执行意图；无成交时不估造价格。

模拟买价 = 参考价 × (1 + 滑点 bps/10,000)，卖价 = 参考价 × (1 - 滑点 bps/10,000)。默认示例滑点 5 bps、每单费用 0 USD，允许实例创建时修改并全程展示；不宣称该默认值还原真实交易成本。资金不足整单拒绝，不自动缩量；卖出不得超过持仓。金额用固定精度十进制或最小单位整数，明确价格/费用舍入规则。

每个实例在隔离 worker 执行可信本地 TypeScript 策略，设超时和输出大小上限；worker 是故障隔离而非恶意代码安全沙箱。首版通过仓库内策略目录及注册表编译加载，不做在线代码编辑器或任意远程脚本下载。策略版本保存源码快照/哈希、构建版本、参数和状态 schema；不依赖可变文件重现旧运行。

### 账本与恢复

新增 SQLite 文件位于 app userData，旧组合 JSON 不迁移为虚构历史。建议表：`instruments`、`strategy_versions`、`runs`、`bars`、`decisions`、`orders`、`fills`、`cash_ledger`、`positions`、`equity_snapshots`、`run_events`、`corporate_actions`、`checkpoints`。

- `run_id` 是账户隔离边界；决策以 `(run_id, bar_batch_id)` 唯一，成交和公司行动分别有幂等键。
- 单一写入服务串行事务提交：成交、现金流水、持仓、事件和检查点必须一致。策略决策与 nextState 同事务持久化；恢复未完成意图前重新判断时效，不重复成交。
- 定时及成交后保存净值，附逐标的价格时间与估值质量。无法取得新价格可展示最后价格估值，但必须标旧，不能生成伪精确的完整收益区间。
- 重启恢复账户和显式策略状态；补拉缺失 bar 仅用于指标预热和查阅，不补做断线期间模拟交易。样本测试回放只用于正确性测试，不建设面向用户的历史回测入口。
- 数据库损坏或写入失败使运行暂停，保留原文件；禁止自动清空账本后继续。提供一致性备份/恢复和完整 JSON 导出，不只拷贝活动数据库主文件而遗漏 WAL。
- 分红、拆股/反向拆股首版提供人工录入和核对入口，使用明确事件调整现金/数量/成本；存在碎股时按显式现金替代价格处理并留痕。调整前暂停受影响运行。未经核对的报告标记公司行动未核对，不宣称完整总回报；可疑价格跳变只触发待核对状态，不能自动猜测拆股。

### 绩效与未来消息扩展

净值 = 现金 + 各持仓数量 × 对应估值价；总盈亏 = 净值 - 初始本金；收益率 = 总盈亏 / 初始本金。平均成本法核算已实现盈亏，手续费计入成本/卖出净额，公司行动独立列示。必须可核对“已实现 + 未实现 + 股息等现金收益 = 总盈亏”。

显示分钟净值、日/月收益、运行期最大回撤、成交记录及已平仓交易样本量。最大回撤注明分钟采样，不表示 tick 极值；月度收益使用上期末净值，未完整月份明确标注。数据中断区间标记不完整；不同启动日期的策略只在共同观察区间做公平对比。首版不强制提供年化收益或 Sharpe，避免短期样本误导。

策略运行事件持久化为有版本的 `StrategyEvent`：`eventId`、`schemaVersion`、`runId`、`strategyVersion`、`type`、`occurredAt`、`reason` 和必要摘要。提供按 cursor 读取事件的内部边界。首版无发送器、无平台 SDK、无重试队列、无消息配置 UI；未来适配器独立消费已提交事件，以 eventId 去重，发送失败不得回滚成交。现有 `SOCL` 读取功能不承担消息投递。

## 目标模块与运行形态

```text
主进程 MarketDataService（只读行情、日历、质量检查）
       ↓ 已完成 bar / 新鲜成交参考价
PaperTradingService → 策略 worker → 买卖意图及显式状态
       ↓ 资金与仓位约束 → 模拟执行
SQLite 单写入服务：账本、事件、状态、净值
       ↓ 受限 IPC 查询及增量状态
React 模拟工作台：配置、运行、持仓、历史、对比
```

建议新增 `src/main/paper/`、`src/shared/paper/`、`src/strategies/` 和 `PaperPanel.tsx`。运行器与账户计算保持不依赖 Electron 的纯核心，便于以后迁到常开服务；首版不部署服务端。主进程负责调度与账户权威，worker 只计算策略。

应用最小化/隐藏时继续运行，完全退出或系统休眠时不能运行。生命周期不借用提醒引擎的特殊订阅 ID；新服务自行管理后台需求。正常退出先停止调度、取消未成交意图并落检查点；异常退出通过运行租约/心跳与启动恢复记录识别。用户可暂停、恢复和结束实例：暂停取消待成交意图但保留仓位，仍可估值；结束也不伪造成交，未平仓需明确显示，用户可在有效行情下请求模拟清仓。

## 阶段详情

### Phase 1：契约与可行性验证

目标：在业务实现前证明 SQLite 可在当前 Electron 运行时使用，免费行情接口能够满足需要，固定分钟、成交、成本和状态契约。

预期文件：`src/shared/paper/types.ts`、`schemas.ts`；必要的 `package.json`/锁文件、`electron.vite.config.ts`；无界面验证脚本；本计划中的实际选型记录。

验收清单：
- [x] 确定驱动版本、打包/原生 ABI 加载路径，使用临时数据库验证事务和重启读取；不触碰真实账本。
- [x] 定义 run 状态、行情质量、StrategyEvent、intent/fill 与检查点 schema，以及本计划的舍入、时效参数。
- [x] 有已授权凭证时只读验证代表性股票与 ETF 的 IEX bar/latest trade 权限、时间戳和速率限制；不创建交易账户、不发送订单。
- [x] 没有凭证则记录未验证及精确解阻条件；接口和离线核心可继续，但真实数据链路验收不能完成。不能因此自动购买行情或申请账号。

助手验证：临时数据库/运行时加载实验、类型检查、契约边界测试；记录环境和实际响应元数据，不记录密钥。用户人工验证：实际使用标的是否在账户权限内；无视觉验收。

依赖与备注：SQLite 不可用属于核心依赖阻塞，需修复或审阅替代方案；免费数据无法满足时报告证据并重新选择源，不能无声降级。

实际完成（2026-09-28）：

- 固定 `better-sqlite3@11.10.0`，由 electron-vite 外置依赖，electron-builder 重建原生 ABI 并将驱动解包到 `app.asar.unpacked/node_modules/better-sqlite3`。Electron 31.7.7 / Node 20.18.0 / ABI 125 / macOS arm64 无页面 worker 探针通过临时数据库事务、回滚和关闭重开读取。
- `src/shared/paper/{types,schemas}.ts` 固定运行状态、行情质量、bar、意图、成交、检查点和事件契约。金额为整数微美元；计算中间值使用 bigint；价格、比例成本分摊、碎股现金以 half-up 舍入至微美元，溢出拒绝。全部出售取走剩余成本。仓位上限首版明确为单标的含费用购入成本 / 初始本金；不依赖缺失估值价猜测实时权重。

- 类型检查通过；契约/资金测试并入 Phase 2 测试套件。下一阶段实现和验证独立账本。
